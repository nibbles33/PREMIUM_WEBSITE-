## Architectural Finding: **C — Hybrid Architecture**

Heroes and card surfaces ultimately resolve through `getPageHeroPhotography()` and `placements.ts`, but cards also depend on intermediate config layers that have drifted from the completed hero registry:

| Layer | File | Used by |
|---|---|---|
| Hero registry | `src/data/photography/placements.ts` | All heroes + all card resolvers |
| Explicit slug config | `src/data/pilot-home.ts` | personalFilmstrip, yepCarousel, commercialCategories panel |
| Explicit slug config | `src/data/pilot-auto.ts` | autoRelatedRail |
| Href→slug alias map | `src/lib/buildPilotProductConfig.ts` (`photoSlugFromHref()`) | productRelatedRail via `relatedLinksToProducts()` |
| Industry related links | `src/lib/buildPilotProductConfig.ts` (`industryRelatedLinks`) | productRelatedRail on industry pages |

**Drift mechanism:** `photoSlugFromHref()` maps many commercial hrefs to stale alias slugs (e.g. cyber→professional-offices, D&O→professional-offices, small-business→commercial-insurance) or defaults unmapped hrefs to `commercial-insurance`. Explicit `photoSlug` values in `pilot-home.ts` / `pilot-auto.ts` similarly override destination heroes in a few cases.
